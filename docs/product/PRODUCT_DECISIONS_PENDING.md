# Product decisions: recommended options (recorded 2026-10-06, implementation pending)

The owner asked for these to be decided and parked. Each is a recommendation with the reason and what building it later involves. Nothing here is implemented yet.

| # | Question | Decision | Why | Later work |
|---|---|---|---|---|
| 1 | Guest mode | **Yes, limited.** Browse For You, Explore and story pages, and read or listen to the first chapter, without an account. Saving, following, Library, Create and the rest need an account, with a plain prompt at that moment | First value before sign-up, as the Figma journey shows; a four-screen onboarding is short, but "no account to look" is shorter | Auth gating per action, a guest state in `AuthContext`, and a "Create an account to save this" sheet. Medium |
| 2 | Creators: publish directly or via review | **Submit for review.** A creator's first story, and any story with content notes, goes to review before it is public; creators with a clean record can publish directly | Protects readers and creators, matches the Figma Submit, In Review and Changes requested states, and the moderation model already in the app | Needs a backend review queue and statuses. Until then, publishing stays local and is labelled demo. BACKEND BLOCKED |
| 3 | Moderator access | **Appointed by an admin only.** No self-request in onboarding. Later, a "Request to help moderate" form in Settings that an admin reviews | Moderators hold power over other people's work; self-selection at sign-up is the wrong entry point | Settings item plus the existing role-elevation request (`requestRoleElevation`) and an admin queue. Small to medium |
| 4 | Institutions | **Partner-led and invite-only.** Keep read-only institutional collections. Build the workspace only when a signed partner needs it (decision D-12 stands) | The rule is no real organisation named as a partner without a signed agreement; a workspace with no partner is dead UI | None until a partner signs |
| 5 | Rename "For You" to "Home" | **Yes, rename to Home (FR Accueil, ES Inicio).** Keep the route id `for-you` | The screen is mostly editorial rails plus an interests rail and Keep reading, not a feed ranked per person; "For You" promises more than it does and reads as social-app language | One PR: strings, `ForYouScreen` heading, bottom nav, error boundary, about 12 test and e2e assertions, docs |
| 6 | News vs Media | **Do not add either.** Neither exists in the app, the data model or Figma. Formats (read, listen, watch) and themes already cover the need | Two empty top-level destinations would add load without content | If editorial news is ever wanted, add it as a collection or a theme first |
| 7 | Re-rank For You by follows | **No re-ranking. Add a "From creators you follow" rail** that appears only when the viewer follows someone with a published story | Honest and visible; re-ranking without enough data would feel random and would need explaining | Small: read follows from `services/creators`, filter stories by creator |
| 8 | Scroll restoration when going back to Explore | **Yes.** Remember the scroll position per route for the session and restore it on Back | Cheap, clearly better, and part of the Figma back-navigation rules | Small: per-route `sessionStorage` map in `App.tsx`, restore after content loads |
| 9 | French and Spanish for older components | **Yes, in stages.** Move strings into `i18n/strings.ts` in this order: bottom nav and header (done), onboarding, Explore, Library, Profile, player, Create Story, Funding. Ship EN/FR/ES for each stage; a native speaker reviews the FR and ES before release | The language choice is the first thing a user sets; half-translated screens undercut it | Several PRs; needs native review. Medium |

Suggested order: 8 and 7 (small, visible), 5 (one clean PR), 9 in stages, then 1 and 3. Items 2 and 4 wait for backend and a partner.
